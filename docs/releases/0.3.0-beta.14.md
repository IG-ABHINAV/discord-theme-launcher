# 0.3.0 beta 14 — Lighter personal themes inside Discord

Personal themes no longer force Discord to restyle its whole window whenever the chat, member list or voice channel changes. This mainly helps busy chats and joining voice channels.

## Changes

- The target guard (`:has()` on the selected server/DM) was the scope root of every rule. Chromium re-evaluated it for the whole Discord tree on each DOM change. It is now evaluated once on the app root, which sets a per-theme flag; all other rules are gated by `@container style()` on that inherited flag.
- Synthetic Chromium benchmark (9,300 Discord-like nodes, one personal theme): about **170 ms → 0.6 ms** per DOM mutation (message insert, voice participant insert, selection or `aria-hidden` change). Without themes the same operations take about 0.05 ms. The images embedded in themes had no measurable effect.
- Targeting behavior is unchanged: exact servers and DM chats, hidden rail and ambiguous selection fail closed, imported themes and multiple targets keep working.

## Upgrade

Download **DiscordThemeLauncher-0.3.0-beta.14-windows-x64-portable.zip**, extract it and run `DiscordThemeLauncher.exe`. **Reapply your theme** (Editor → Review & apply) so the installed `PersonalServer.theme.css` is regenerated; already installed files keep the old, heavier structure. Applying also disables older launcher presets still enabled in Vencord.

Both the ZIP and the standalone EXE bundle .NET, require Microsoft Edge WebView2 Runtime and remain **unsigned**.

## Validation and limits

Local validation: 142 Core checks and 72 browser tests, including server/DM isolation, hidden rails, ambiguous selection, imported themes and multi-target output. The benchmark is synthetic; it is not a measurement of the live Discord client, network latency of voice connections or Discord's total RAM. Bundled preset files (PrimeBuild, FantaFort, PrimeBuildDev) are no longer installed by the app and keep their previous structure.
