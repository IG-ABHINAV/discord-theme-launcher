# 0.3.0 beta 16 — In-app updates and automatic cleanup

Theme Studio can now update itself, and every new version tidies up the themes installed by older versions so they use the current, faster format. All your themes stay enabled.

## Changes

- **Update to …** appears in the header when GitHub has a newer release. One click downloads that release's EXE, verifies it against `SHA256SUMS.txt`, replaces the app in place and restarts it. Only the version number is read from the GitHub API; download URLs are rebuilt for this repository. Nothing is downloaded without the click.
- **Automatic cleanup on start.** Enabled launcher files from older versions are migrated: saved themes are recompiled by this version into their own `Studio-<id>.theme.css`, bundled presets become saved themes in My themes, and the old single personal slot is matched to its saved theme. External themes, plugins and QuickCSS are untouched and a recovery snapshot is taken first.
- If Discord is closed the cleanup runs immediately. If it is open, **Optimize installed themes** appears and restarts Discord when clicked; right after an in-app update it runs automatically.

## Upgrade

Versions up to beta.15 have no updater: download **DiscordThemeLauncher-0.3.0-beta.16-windows-x64-portable.zip** (or the standalone EXE) once, extract it and run it in place of the old app. It cleans up the installed themes itself; no separate script is needed. From beta.16 on, updates are offered inside the app.

Both the ZIP and the standalone EXE bundle .NET, require Microsoft Edge WebView2 Runtime and remain **unsigned**. The in-app update relies on GitHub HTTPS and the release checksum, not on a code signature.

## Validation and limits

Local validation: 159 Core checks, 74 browser tests and 90 native Windows checks. Core checks cover version ordering, release selection (drafts and malformed tags ignored), checksum lookup, and migration of a legacy personal slot, raw `:has()` presets and per-theme files from an older compiler, including idempotence and recovery. The executable swap was exercised on the development machine after publication.
